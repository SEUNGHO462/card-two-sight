# 팀원 작업 영역과 연결 약속

현재 구현된 파일을 기준으로 정리한 **앞으로의 담당 제안**입니다. 실제로 누가 어떤 작업을 했는지를 나타내는 기여 기록은 아닙니다.

## 3인 역할 분담

| 팀원 | 역할 | 담당 영역 | 구체적인 작업 |
|---|---|---|---|
| 한승호 · 2500200 | 게임 규칙·기록·통합 및 검증 | common의 GameEngine.java, core/game의 RecordStore.java | 숫자 대결, 특수카드 효과, 라운드·점수·목숨·실탄 판정, 기록 저장, 전체 기능 연결 및 테스트 |
| 오지민 · 2500112 | 화면·디자인·연출 | core/screens, core/ui, assets | 메인·캐릭터 선택·접속·대기방·카드 대결·룰렛·최종 결과 화면, 버튼 입력, 장전·회전·격발 연출, 이미지·글꼴·음향 |
| 이지향 · 2300430 | 네트워크·서버 | server, core/network | 서버 실행, 방 생성·입장, 두 플레이어 연결, 명령 전송, 개인별 상태 동기화, 접속 종료 처리 |

표의 폴더는 모듈 내부 자바 패키지를 줄여 표시한 것입니다. 예를 들어 core/screens는 core/src/main/java/kr/ac/c2s/screens입니다.

### 폴더 이름만으로 나누지 않을 파일

- core/game/ShotTimeline.java와 CylinderPreparation.java는 화면 연출의 진행 시간을 다루므로 **오지민 담당**입니다.
- common/Protocol.java는 세 파트가 공유하는 데이터 약속입니다. **이지향이 수정 담당**을 맡고, 승패·목숨·특수카드 등의 필드 변경은 한승호와 확인합니다. 화면에 필요한 필드는 오지민과도 확인합니다.
- core/C2SGame.java는 화면·통신·게임을 연결하는 공통 파일이므로 **한승호가 통합 담당**으로 수정합니다. 화면 전환이나 접속 흐름을 바꿀 때 관련 담당자와 맞춥니다.
- 실행 설정과 공통 빌드 설정은 한승호가 취합합니다. 공통 파일을 여러 사람이 동시에 크게 고치지 않습니다.

## 서로 연결할 때 지킬 약속

1. 화면은 C2SGame.send(Protocol.Command)를 통해 행동을 전달합니다. 화면에서 승패나 실탄 수를 따로 계산하지 않습니다.
2. 서버는 GameEngine.apply(플레이어 번호, 명령)로 규칙을 실행하고 snapshot(플레이어 번호)로 해당 사용자에게 허용된 상태를 보냅니다.
3. Protocol.Snapshot에 상대의 비공개 숫자나 실탄 배치를 추가하지 않습니다. 개인 정보는 해당 사용자에게만 전달합니다.
4. GameGateway는 온라인 모드와 연습 모드가 함께 쓰는 연결점입니다. 서버 응답은 Gdx.app.postRunnable을 통해 화면에 반영합니다.
5. 함수명뿐 아니라 매개변수, 반환값, 데이터 필드, 호출 시점까지 맞춥니다. 약속을 바꾸면 docs/INTERFACES.md도 함께 수정합니다.
6. 캐릭터 식별자·이미지 경로·화면에서 사용하는 상태 이름을 바꾸면 해당 담당자에게 알립니다.

예를 들어 룰렛에서는 오지민이 장전·탄창 회전·버튼과 결과 연출을 만들고, 이지향이 탄실 선택 명령과 개인별 결과를 전달하며, 한승호가 실탄 판정·목숨 감소·게임 종료를 처리합니다.

## GitHub에서 합치는 순서

1. 현재 프로젝트 전체를 공통 기준으로 저장소에 올립니다. .tools, .gradle, build, .runtime는 올리지 않습니다.
2. 모두 같은 저장소를 내려받고 담당 기능별 브랜치에서 작업합니다. 사람마다 서로 다른 새 프로젝트를 만들지 않습니다.
3. 담당 영역을 작은 단위로 수정합니다. 공통 파일 변경은 수정 담당자가 취합합니다.
4. 올리기 전에 테스트와 담당 화면 실행을 확인합니다.
5. 합친 뒤에는 연습 한 경기와 실제 두 클라이언트 접속을 확인합니다.

지금은 파일을 대규모로 옮기기보다 이 담당표로 작업 경계를 정하는 것이 좋습니다. 화면별 파일이 이미 분리되어 있어 현재 구조를 그대로 활용할 수 있습니다.
